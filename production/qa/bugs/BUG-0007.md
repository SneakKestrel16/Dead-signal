# Bug Report

## Summary
**Title**: Eliminated clients never see Results after the shapeshifter wins by elimination
**ID**: BUG-0007
**Severity**: S2-High
**Priority**: P2-Fix next sprint
**Status**: Fixed
**Reported**: 2026-10-15
**Reporter**: MF-14 agent (match-flow story 014), while capturing live Results evidence

## Classification
- **Category**: Gameplay / Network
- **System**: network (`ServerMovement`), match-flow (spectators, story 007)
- **Frequency**: Always, when the last survivor is eliminated
- **Regression**: No

## Environment
- **Build**: wt-mf14 at `02f4c78` (MF-14 merge)
- **Platform**: Windows 11, Godot 4.7.2

## Reproduction Steps
1. Host a lobby round with the host seat as a survivor.
2. Let every survivor be eliminated.

**Expected Result**: every client receives the RoundEnded batch and shows the Results screen.
**Actual Result**: the eliminated clients never show Results. The server payload is correct.

## Cause (from the MF-14 report; not re-verified by the orchestrator)
- `ServerMovement._snapshot_phase` in `src/foundation/network/server_movement.gd` skips any spectator whose watched survivor has no body: `if not _players.has(watched): continue`.
- When the last survivor is removed, no spectator gets that tick's event batch, so RoundEnded never arrives.

## Workaround
- The MF-14 evidence used `--lobby-seed=6`, which makes the host the shapeshifter. That seat is never removed.

## Fix direction
- A spectator with nothing to watch still receives the tick's event batch.

## Fix
- Commit `ad2f0e6` on wt-bug7 (fix: BUG-0007 ...). Cause confirmed, and a second path found: the last survivor out never got a `watch` at all (`RoundLifecycle._retarget` returned with no target), so it was neither a body nor a spectator in `ServerMovement`.
- `ServerMovement._snapshot_phase`: a spectator whose watched survivor has no body, or who watches -1, still gets the handle messages and the event batch (catch-up and `batch_extras` included), projected as the watched survivor, or as itself when it watches -1 (ADR-0004 per-peer projection kept). No sounds and no snapshot: there is no body for the own entry, so the client holds its last view.
- `ServerMovement.watch(spectator, -1)` is accepted (no target yet). `RoundLifecycle._retarget` with nobody watchable calls `watch(sp, -1)` for every spectator that never watched anyone. `RoundComposer._watch` skips the ViewOffset resend for -1.
- Test: `tests/integration/match-flow/all_survivors_out_round_ended_test.gd` (real ENet, ports 30920-30939): two real clients dealt survivors, all four survivors eliminated, both clients receive RoundEnded. It failed before the fix. Three mutations were each caught: the old `continue`, no `watch(sp, -1)`, and the old `watch` early return.
- `spectators_and_reconnect_state_test.gd`: the no-survivor-left case now expects one `[last, -1]` watch call. Not run here, because it is another suite's ENet range.
