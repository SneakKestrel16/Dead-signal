# Bug Report

## Summary
**Title**: At round end the host's RoundClient keeps predicting after the peer is gone, and replication teardown logs disconnect errors
**ID**: BUG-0015
**Severity**: S4-Low
**Priority**: P3-Fix when convenient
**Status**: Verified Fixed
**Reported**: 2026-10-15
**Reporter**: orchestrator, from the designer's playtest log (main `83b5704`, host on port 31210)

## Classification
- **Category**: Network / Log noise
- **System**: match-flow (client round scene, story 011; lobby-to-round wiring, story 013)
- **Frequency**: Once per round end, on the host
- **Regression**: Unknown

## Environment
- **Build**: `83b5704`
- **Platform**: Windows 11, Godot 4.7.2, windowed host via `main.tscn` with `--lobby-host --lobby-seed=6`, 3 headless joiners

## Reproduction Steps
1. Host a lobby round and play it to the end (here: all survivors bled out).

**Expected Result**: the round scene stops sending before the round's peer closes, and teardown logs no errors.
**Actual Result**: the host log shows:
- `ERROR: Trying to send a raw packet while no multiplayer peer is active.` from `predict (owner_predictor.gd:107)` called by `_physics_process (round_client.gd:408)`.
- 7 pairs of `Attempt to disconnect a nonexistent connection from 'Sync:<MultiplayerSynchronizer#...>' ... visibility_changed` plus `Condition "!tracked_nodes.has(oid)" is true` from `on_replication_stop`.
- 7 lines of `Condition "!sync" is true`.
The Results screen still showed, and play was not affected.

## Evidence
- Playtest host log (not retained). Re-run the steps to reproduce.

## Fix direction
- Stop RoundClient's physics processing (or the predictor) before the peer is closed at round end.
- Free the round's MultiplayerSynchronizers before the replication interface resets, in that order.

## Fix
- Root cause 1: `RoundClient.close()` closed the seat's session but left `_physics_process` running until the queued free, so `OwnerPredictor.predict` sent on a null peer. `close()` now sets `_lost`, which stops prediction and every send.
- Root cause 2: `LobbyScreen._drop_round()` unrooted the seat's SceneMultiplayer (`set_multiplayer(null, seat)`) before the queued seat left the tree. The seat's synchronizers then stopped replication on the lobby's own multiplayer, which never tracked them (`nonexistent connection` and `!tracked_nodes.has(oid)`), and the seat's API later reset over freed synchronizers (`!sync`). The seat is now unrooted on its `tree_exited`.
- Regression test: `tests/integration/match-flow/round_end_teardown_test.gd` (real ENet, ports 31000-31019). It failed before the fix with all four messages, and each half of the fix, reverted alone, fails it.
- Live check, 2026-10-15: `results_stats_host.tscn` host headless on port 31020 with `--lobby-seed=6` and 3 headless joiners. Host log before the fix: 1 raw-packet, 7 nonexistent-connection, 7 tracked_nodes and 7 `!sync` errors. After the fix: 0 of each.
