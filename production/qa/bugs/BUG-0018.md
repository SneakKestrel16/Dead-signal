# Bug Report

## Summary
**Title**: Doors and barricades have no physical effect in a round: door state never reaches the physics blockers or the clients, so a closed or barricaded door neither stops a body nor is drawn
**ID**: BUG-0018
**Severity**: S2-High
**Priority**: P1-Fix this sprint
**Status**: Fixed
**Reported**: 2026-10-15
**Reporter**: orchestrator, from the level-geometry agent (wt-walls, AD-249)

## Classification
- **Category**: Gameplay / Network
- **System**: facility-map (Doors, DoorBlockers), survivor-defense (barricades), match-flow (`round_composer.gd`)
- **Frequency**: Always
- **Regression**: No. It was hidden because the greybox had no walls, so nothing could be blocked anyway

## Environment
- **Build**: `9fcbdc4` plus the wt-walls level geometry
- **Platform**: Windows 11, Godot 4.7.2

## Reproduction Steps
1. Start a round with the level geometry from wt-walls (walls on WORLD and glass on GLASS from `assets/levels/research_facility.tscn`).
2. Close a door, or barricade a Zone C door.
3. Walk into it as either role.

**Expected**: the closed or barricaded door blocks bodies and lunges (`movement_step.gd` lunge stop list; level doc Fixtures; survivor-defense barricade rules), and every client draws the leaf in its current state.
**Actual**:
- Door state changes only sight and interaction. Bodies pass through, and no leaf is drawn.
- `Doors.blockers` is never set in `round_composer.gd`, so the scene's door blockers stay disabled.
- Door state is not replicated to clients.

The scene's exit blocker also started closed with nothing to open it, so wt-walls force-opens it (match-flow decides when an escape counts).

## Root cause (from the wt-walls agent's reading; inference until a fix confirms it)
Physical door blocking and door-state replication were never wired. `DoorBlockers` exists (`src/core/facility/door_blockers.gd`) but nothing gives it to `Doors` on the host, and clients have no door state to draw from.

## Fix direction
- Wire `DoorBlockers` into `Doors` on the host so closed doors enable the leaf collider.
- Replicate door open, closed and barricaded state to clients, using the existing replication pattern, as `lighting_replication.gd` does.
- Draw the leaf (ASSET-048/049) from that state.
- Re-check the tick budget (`chase_closing_tick_budget_test`), because enabled blockers add colliders.

## Related
AD-249, ASSET-048, ASSET-049, story survivor-defense/014 (AD-219).

## Fix (2026-10-15, wt-bug18: 004b41a, 4e23f93, a58fa80)
- Doors drive the level's DoorBlockers on the host. Round bodies now collide on `PhysicsLayers.MOVE_PREDICT` (walls, glass, doors) on the server and in the owner's prediction. They used WORLD only before, so glass and doors could never block anyone.
- Door state goes to every client as a new event-batch entry, `EventBatch.DOORS` (`DoorStates`), carrying every door's closed flag plus the exit flag. It is resent in full on rejoin. Clients apply it to their own blockers and draw the authored leaf. Barricades draw placeholder planks from the existing barricade entry.
- The exit stays closed until `SurvivorObjectives.exit_open()`; the unused `ExitGate` is still in the repo.
- Tests:
  - `tests/unit/facility-map/door_blockers_test.gd`: 8 tests.
  - `tests/integration/match-flow/door_blocking_round_test.gd`: real ENet; a closed door stops the body on the server and in prediction, and the client receives the state.
  - 5 mutations caught.
- `round_composer_test` batch-extras audit raised from 14 to 15 and now names `doors.door_entries`.

## Verification (2026-10-19, main ae7b55f)
- `door_blockers_test.gd` and `door_blocking_round_test.gd` pass. Still open: no retained screenshot of a closed door's leaf on a client. `tests/manual/round_view.gd` has no bot that closes a door; a `--bot=door` would settle it. Status stays Fixed until then.
