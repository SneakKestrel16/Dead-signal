# Bug Report

## Summary
**Title**: `PingCalloutHud.place` calls `unproject_position` on a point in the camera plane: 664 errors per client in one round
**ID**: BUG-0016
**Severity**: S3-Medium
**Priority**: P2-Fix soon
**Status**: Fixed (f722103)
**Reported**: 2026-10-15
**Reporter**: orchestrator, from the designer's playtest logs (main `83b5704`, port 31210)

## Classification
- **Category**: UI / Log noise
- **System**: pings-and-callouts (H12 `PingCalloutHud`, story 008)
- **Frequency**: Every frame on each headless joiner for part of the round: 664 errors per client log
- **Regression**: Unknown

## Environment
- **Build**: `83b5704`
- **Platform**: Windows 11, Godot 4.7.2; headless clients from `main.tscn -- --lobby-join=127.0.0.1 --lobby-ready`

## Reproduction Steps
1. Host on port 31210 with 3 headless joiners. The joiners never move.
2. Play the round to the end.

**Expected Result**: no engine errors.
**Actual Result**: each joiner log has 664 copies of:
`ERROR: Condition "p.d == 0" is true. Returning: Point2()  at: unproject_position (scene/3d/camera_3d.cpp:495)`
from `_draw (ping_callout_hud.gd:494)` and `place (ping_callout_hud.gd:268)`.

## Notes
- Inference: a marker target lies exactly in the camera plane. Likely causes are a marker at the camera's own position (a ping on the client's own body or position), or a headless viewport with a degenerate camera.
- Whether windowed clients hit it is unknown: the host log has none.
- The ADR-0014 verification measured `place` at 39 us median for 40 markers, so the error path also costs time.

## Fix direction
- Before projecting, skip points with zero depth: `camera.is_position_behind(p)` or a distance check against the camera's near plane. Treat them as off-screen (edge-clamped).

## Fix
- Root cause: `PingCalloutHud.place` called `Camera3D.unproject_position` for every marker. A point in the camera plane (zero camera-space depth) makes it divide by zero and log `p.d == 0`.
- Fix: at that single projection site, a point with zero camera-space depth skips the projection. `is_position_behind` already counts such a point as behind, so `place` takes its direction from camera-space x and y and edge-clamps it like any off-screen marker. `ShapeshifterInstallAlert` calls `place` too, so it gets the same guard.
- Regression test: `tests/unit/pings-and-callouts/ping_place_camera_plane_test.gd`. It covers a marker at the camera position (no error, off-screen, clamped) and a marker level with the camera to the right (right edge, arrow at 0 rad). It failed before the fix.
- Live check: the short `results_stats_host` run on 2026-10-15 logged 0 `p.d == 0` lines both before and after the fix, so it does not reproduce the playtest's 664. A full-length round with idle joiners would settle the live count. Inference: the cause is the one the test covers.
