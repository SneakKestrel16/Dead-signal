# Bug Report

## Summary
**Title**: Unranged int knobs (net.port, history_ticks, input_queue_cap, ...) and unranged alpha floats load any finite value
**ID**: BUG-0002
**Severity**: S3-Medium
**Priority**: P2-Fix next sprint
**Status**: Verified Fixed
**Reported**: 2026-10-14
**Reporter**: SR-1 retroactive Sprint 1 code review (godot-gdscript-specialist finding, verified)

## Classification
- **Category**: Data / Config
- **System**: data-config (`src/foundation/data_config/`)
- **Frequency**: Always (when a knob file holds such a value)
- **Regression**: No (present since data-config story 001)

## Environment
- **Build**: `d65b541` plus the SR-1 fixes
- **Platform**: Windows 11, Godot 4.7.2
- **Scene/Level**: none (unit level)
- **Game State**: knob load

## Reproduction Steps
**Preconditions**: none.

1. In `data/knobs/net.tres`, set `port = -1` or `tick_estimate_rise_alpha = 7.0`.
2. Run `Knobs.load_all().errors()`.

**Expected Result**: an error naming the field and its range.
**Actual Result**: `[]`. `KnobValidator.validate` skips every field without a `PROPERTY_HINT_RANGE`, so only the unset check applies.

## Technical Context
- **Likely affected files**: `src/foundation/data_config/net_knobs.gd` (plain `@export` ints and floats such as `port`, `history_ticks`, `input_queue_cap` and the `*_alpha` values), `src/foundation/data_config/controller_knobs.gd` (lines 14, 27-28, 36-40).
- **Related systems**: refuse-to-host (data-config story 003) relies on `errors()`.
- **Possible root cause**: these knobs have no sourced Safe Range, so they were left with a plain `@export`. Each needs a range from its GDD or ADR (port: 1-65535 is a protocol fact; alphas: 0-1 by definition of an EMA weight).

## Evidence
- **Logs**: none; reproduced by reading `knob_validator.gd:21`.
- **Visual**: none.

## Related Issues
- `production/qa/sr-1-sprint-1-review-2026-10-14.md`
- Partly fixed in SR-1: non-finite floats (INF) are now rejected for every float knob, ranged or not, and `core.max_flush_rounds` has a range.

## Notes
Ranges must be sourced (CLAUDE.md coding standards: balance values link to their source). Fix by adding `@export_range` with a source comment per field, plus one out-of-range test per field group.

## Resolution
**Fixed**: 2026-10-14, Sprint 5 (AD-126).
- Every int knob and every `*_alpha` / `*_mult` float in `src/foundation/data_config/*_knobs.gd` now has an `@export_range` with a source comment. The `starvation_*` fractions and the unranged controller floats got ranges too.
- Sourced: `net.port` 1..65535 (UDP); the EMA alphas and starvation fractions 0..1 (definition); `facility.max_flashes_per_s` 0..3 (scare-events.md rule 25, proposed); `lobby.name_min_chars` / `name_max_chars` 1..16 (lobby-role-assignment.md rule 3).
- Marked `inference` in the code, each naming what settles it: `net.interp_delay_ms`, `max_extrapolation_ms`, `history_ticks`, `max_clients_headroom`, `auth_payload_cap_bytes`, `enet_timeout_limit` / `_min_ms` / `_max_ms`, `input_queue_cap`, `max_seq_ahead`, `input_packet_cap_bytes`; `controller.max_survivor_sprint_mps`, `intent_timeout_ms`, `capsule_height_m`, `capsule_low_height_m`, `floor_max_angle_deg`, `floor_snap_length_m`, `safe_margin_m`, `max_slides`, `wall_min_slide_angle_deg`.
- Regression test `tests/unit/data_config/knob_ranges_test.gd` (5 tests) derives the field list from the scripts; 3 of its tests failed before the fix and pass after it.

## Verification
**Verified**: 2026-10-15, /team-qa sprint-005. `tests/unit/data_config/knob_ranges_test.gd` passed 5/5 in the full suite at `72a2e69` (898/898), including `test_ranges_port_zero_is_reported_by_errors` and `test_ranges_alpha_above_one_is_reported_by_errors`, 3 of which failed before the fix.
