## Reproduction Steps
**Preconditions**: none.

1. Start a host: `<godot> --headless --path . --quit-after 900 res://tests/manual/net_check.tscn -- --role=host --port=24771`
2. Start a client: `<godot> --headless --path . --quit-after 500 res://tests/manual/net_check.tscn -- --role=client --host=127.0.0.1 --port=24771 --name=Smoke --mode=route`
3. Let the host quit first (headless frame counts run at different speeds).

**Expected Result**: the client prints `HOST_LEFT` and stops sending.
**Actual Result**: the client prints `server_disconnected` and `HOST_LEFT`, then logs `ERROR: Trying to send a raw packet via a multiplayer peer which is not connected.` once per tick (17 times here) until it quits.

## Technical Context
- **Likely affected files**: `tests/manual/net_check.gd` (route loop keeps calling `OwnerPredictor.predict`); possibly `src/foundation/network/owner_predictor.gd` (`predict` sends without checking the connection status).
- **Related systems**: NetAuthority `host_left`; in the game, `Main.return_with` leaves the scene on `host_left`, so only the harness hits this.
- **Possible root cause**: the route loop does not stop on `host_left`. Fix there, or guard the send in `OwnerPredictor.predict` with the peer's connection status.

## Fix
- **Root cause**: `OwnerPredictor.predict` called `SceneMultiplayer.send_bytes` without checking the peer. After `server_disconnected` the client's ENet peer is closed, and `send_bytes` fails its `CONNECTION_CONNECTED` check with an engine error on every tick. The harness route loop is one caller; `RoundClient` could hit the same window between `host_left` and leaving the scene.
- **Change**: `src/foundation/network/owner_predictor.gd` sends only when the multiplayer peer exists and is `CONNECTION_CONNECTED` (one guard in the shared send, so every caller is covered). Local prediction still runs.
- **Regression test**: `tests/unit/network/owner_predictor_disconnected_test.gd` predicts three ticks on a closed ENet client peer with a `Logger` installed and asserts no engine error. Before the fix: fails with 3 x `send_bytes ... Trying to send a raw packet via a multiplayer peer which is not connected.`; after: passes.
- **Mutations**: guard removed (pre-fix code) -> caught; guard compares with `CONNECTION_DISCONNECTED` -> caught.
- **Run evidence** (2026-10-16, headless, host `--quit-after 300` on port 30771/30772, client `--quit-after 1500 --mode=route`): before the fix the client logged 569 `not connected` errors after `HOST_LEFT`; after, 0 (`PLAYER_ID 0`, `c0 RTT 7 ms`, `c0 server_disconnected`, `c0 HOST_LEFT`, then nothing).
- **Suites**: `tests/unit/network` (incl. the new file), `tests/unit/event_catalog`, `tests/integration/network/prediction_reconcile_test.gd` alone: all pass.
- **Commit**: see `git log -- production/qa/bugs/BUG-0001.md` (worktree branch wt-bugs).
