# Bug Report

## Summary
**Title**: Reduced motion does not stop the interaction prompt fade (and marker fade-out); no setting reaches reduced_motion
**ID**: BUG-0008
**Severity**: S3-Medium
**Priority**: P2-Fix soon
**Status**: Verified Fixed
**Reported**: 2026-10-15
**Reporter**: HUD-10 agent (hud-results story 010), budget and accessibility pass

## Classification
- **Category**: UI / Accessibility
- **System**: hud-results (H7 `InteractionHud`, story 003); pings-and-callouts (H12 `PingCalloutHud` marker fade)
- **Frequency**: Always
- **Regression**: No

## Environment
- **Build**: wt-hud10 at `87c3058`
- **Platform**: Windows 11, Godot 4.7.2, 1920x1080 windowed, `--write-movie --fixed-fps 30`

## Reproduction Steps
1. Host: `round_host.gd -- --port=30901 --players=6 --force=15:evac`.
2. View: `round_view.tscn ... -- --port=30901 --count=6 --view=survivor --bot=budget --reduced-motion --shots=<dir>`.
3. Compare prompt_00..07.png (8 consecutive HUD-only frames from the frame the prompt first shows).

**Expected Result**: hud.md Accessibility: with reduced motion on, fades become cuts; the prompt is at full alpha on its first drawn frame and the prompt zone does not change after it.
**Actual Result**: The prompt fades in over 3 drawn frames at 30 fps: peak luminance in the prompt rect (880,570,160x45) is 0.471, 0.786, 1.000 on frames 0-2; `hud_measure.py motion --rect=660,560,600,80` reports 5364 and 5304 changed pixels on frames 1 and 2, 0 after. `InteractionHud` has no reduced_motion property (its header says so) and `PingCalloutHud` fades markers out over FADE_S unconditionally. Also nothing sets `reduced_motion` on AlwaysOnHud, EdgeCues or OwnStateHud in `round_client.gd`: a player cannot turn it on (the harness sets it directly).

## Evidence
`production/qa/evidence/hud-budget-accessibility/prompt_00.png`..`prompt_07.png`; numbers in `production/qa/evidence/hud-budget-accessibility-evidence.md`.

## Fix direction
A reduced_motion property on InteractionHud and PingCalloutHud (alpha 1 / 0 immediately), and one place in RoundClient that pushes the Accessibility setting to every HUD presenter.

## Fix
Commit 0ccd197 (round_client push in same commit; round_view helper in the follow-up commit). Test: tests/unit/hud-results/prompt_hold_ring_reject_test.gd (prompt_alpha, label_alpha), tests/unit/pings-and-callouts/ping_callout_presentation_test.gd (marker cut), tests/unit/hud-results/reduced_motion_push_test.gd. InteractionHud and PingCalloutHud got `reduced_motion`; `RoundClient.set_reduced_motion` / `push_reduced_motion` is the one place that sets it on every HUD child. INFERENCE: no client settings store exists, so the initial value is the `--reduced-motion` user flag (a settings store replaces that one line). After: `hud_measure.py motion --rect=660,560,600,80 prompt_0*.png` = 0 changed pixels on frames 1-7 (was 5364 / 5304 on frames 1-2); `after/bug-0008-prompt_00.png`.
