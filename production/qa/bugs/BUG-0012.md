# Bug Report

## Summary
**Title**: `test_killed_server_is_detected_by_the_client_within_the_enet_timeout` fails intermittently: the client detects a killed host in 3.7-4.3 s against a 3.02 s bound
**ID**: BUG-0012
**Severity**: S3-Medium
**Priority**: P2-Fix soon
**Status**: Open
**Reported**: 2026-10-15
**Reporter**: orchestrator, while merging the BUG-0008..0011 fixes

## Classification
- **Category**: Network / Test reliability
- **System**: network (disconnect and host-left detection)
- **Frequency**: 2 of 3 runs alone at `b024355`; 3 of 3 at `6e487e8`; passed in the sprint-9 smoke run at `6e487e8` an hour earlier
- **Regression**: Unknown. It fails at the commit before the merge too, so the merge did not cause it

## Environment
- **Build**: `6e487e8` and `b024355`
- **Platform**: Windows 11, Godot 4.7.2, loopback; no other Godot process running

## Reproduction Steps
1. Run `tests/integration/network/disconnect_host_left_test.gd` alone, three times.

**Expected Result**: `host_left` fires within `enet_timeout_max_ms + ENET_PING_INTERVAL_S + tick` (3.017 s).
**Actual Result**: it fires after 3.765 s and 4.276 s in two failing runs. The sibling server-side test (`test_killed_client_is_reported_dropped...`) detects in 1.17-1.22 s every run.

## Notes
- The server side detects in about 1.2 s, while the client side takes 3.7-4.3 s. Inference: the client's peer to the host may not get the same `set_timeout` as the server's peers, or `host_left` waits on something after the disconnect. Reading where `set_timeout` is applied on the client would settle it.
- Do not widen the bound (house rule).
