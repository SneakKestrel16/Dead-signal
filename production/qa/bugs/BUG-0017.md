# Bug Report

## Summary
**Title**: Exported build does not start: shipped round code uses the test helper `TestMoveStep`, which the export excludes, so movement in the shipped game is the test stand-in (walk only)
**ID**: BUG-0017
**Severity**: S1-Critical
**Priority**: P1-Fix this sprint
**Status**: Verified Fixed
**Reported**: 2026-10-15
**Reporter**: orchestrator, first export of the "Dead Signal Windows" preset

## Classification
- **Category**: Build / Gameplay
- **System**: match-flow (RoundHost, story 013), lobby (LobbyScreen), controller (MovementStep)
- **Frequency**: Always, in an exported build
- **Regression**: No. It has been this way since MF-13. The editor and tests load `tests/`, which hid it

## Environment
- **Build**: `2f74a02`, exported with `--export-release "Dead Signal Windows"`
- **Platform**: Windows 11, Godot 4.7.2

## Reproduction Steps
1. Run `godot --headless --path . --export-release "Dead Signal Windows" build/windows/DeadSignal.exe`.
2. Run `build/windows/DeadSignal.exe --headless --quit-after 5`.

**Expected Result**: the game boots.
**Actual Result**:
```
SCRIPT ERROR: Parse Error: Identifier "TestMoveStep" not declared in the current scope.
SCRIPT ERROR: Compile Error: Failed to compile depended scripts.
ERROR: Failed to load script "res://src/main.gd" with error "Compilation failed".
```

## Cause
- The preset excludes `tests/*`.
- `src/feature/match_flow/round_host.gd:89` and `src/ui/lobby/lobby_screen.gd:343` pass `TestMoveStep.apply` and `TestMoveStep.make_body` from `tests/helpers/test_move_step.gd`. RoundHost's header says the real controller step had not shipped yet, and to swap both sides when it does.
- `TestMoveStep.apply` is walk-only at 4 m/s. Inference: sprint, crouch and the gait speeds of `MovementStep.step` do not apply in the shipped lobby round. The designer's playtest did not check sprint or crouch.

## Fix direction
- Ship a `src/` movement step and body factory on `MovementStep.step` (with per-body `MoveState` and `Knobs`), and use it in RoundHost and LobbyScreen.
- Leave `TestMoveStep` for tests.
- Add a guard that fails when any `src/` file names a class defined under `tests/`.

## Fix
- `src/core/controller/round_move_step.gd` (`RoundMoveStep`): `MovementStep.step` behind the shared Callable(body, frame, modifiers), knobs bound (`step_for(knobs)`), one `MoveState` per body in its meta, `frame.crouch` feeding the crouch gait, the Lunge dash and root/lock/slow/turn-cap from the owner's `MovementModifiers`. `body_maker(knobs)` builds a `PlayerBody` (ADR-0007 values from ControllerKnobs) on PLAYERS colliding with WORLD only, as the harness bodies did.
- RoundHost (server) and LobbyScreen's RoundClient (owner prediction) both use it, so prediction and server run the same step. TestMoveStep stays for tests and tests/manual.
- `tests/integration/network/prediction_reconcile_test.gd` now runs on RoundMoveStep (9/9 pass), so the reconcile proof covers the shipped step.
- Guard: `tests/unit/smoke/src_uses_no_test_class_test.gd` fails when any src/ script names a class defined under tests/ (watched it fail on round_host.gd:89 and lobby_screen.gd:343).
- Not done: the crouch posture (PlayerBody.set_low, the low capsule) is still not driven in the round; only the crouch speed applies. No round module drives it yet.
- Verified: export, `DeadSignal.exe --headless --quit-after 5` prints `boot ok`, no SCRIPT ERROR; exported host on port 31110 plus 3 exported joiners started a round, 0 SCRIPT ERROR in the 4 logs.

## Verification (2026-10-19, main bb60469 + teardown fix)
- Export of "Dead Signal Windows": exit 0, no error lines. `DeadSignal.exe --headless --audio-driver Dummy --quit-after 5` prints `boot ok: knob problems=0`.
- Exported host on port 31110 and 3 exported joiners (`--lobby-ready`, `--quit-after 4000`) composed a round: objective points and ambience logged, no SCRIPT ERROR.
- That run showed two teardown errors, fixed in the same commit (`src/ui/lobby/lobby_screen.gd`). On quit, the host's `_drop_round` read `get_path()` on a seat that had already left the tree. The clients got `grab_focus` on a form already out of the tree after "Host left". Re-run from the editor binary: 0 errors on the 3 clients. The host still logs only `1 resources still in use at exit` when it is killed mid-round.
